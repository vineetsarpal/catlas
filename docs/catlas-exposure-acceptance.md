## Authorized release and hosted drill sequence

This is an execution plan for Vineet to review. Preparation of the plan is not permission to execute it. The [Cloudflare guide](catlas-cloudflare.md), [archive README](../services/exposure-archive/README.md) and maintenance runbooks contain detailed commands and secret-handling rules.

1. **Review the approved capacity revision and candidate.** CAT-44’s reopened capacity choice is resolved by the explicit 768 MB / 256 MB approval. Verify effective hosted usage and fit after the separately authorized release; source approval does not activate deployment/Cron. Inspect the source/config manifest, additive schema diff, lockfiles, regression results, offline ZIP and limitations. Export any browser-local cases needed before changing origin; histories do not migrate between origins. Preserve current hosted version IDs, manifests, private inventory and existing original-byte hashes as the before-state.
2. **Approve named actions and resources.** Distinguish updating the existing disposable proof Worker and Pages from new clean restore resources, private administrative secret setup, live data changes and activation. Name the Neon project/database, R2 bucket, Worker and selected plans for a disposable hosted restore/fault drill. No paid upgrade, production provisioning or destructive live cleanup is implied by CAT-57 approval.
3. **Protect the current archive.** Confirm present storage usage, private originals, resource plans, access and recovery inventory before changes. Retain original public identities/hashes; do not use an arbitrary smaller backup declaration to reclaim capacity. An additive migration is not a substitute for a complete backup. If the deployed older runtime cannot provide one, establish a reviewed provider-level preservation/export procedure before changing it.
4. **Apply matching schema before dependent runtime.** Use the explicit private migration process against the approved target only. The CAT-53 capture-history, CAT-55 lifecycle/cleanup and CAT-56 recovery additions must accompany their reviewed runtime. Securely configure the distinct Worker-only administrative credential. Avoid pushing main before this ordering is resolved because both Pages and archive deployment automation may run.
5. **Release the approved runtime and bridge.** Deploy the reviewed archive Worker/config, retain its deployed version and effective vars/bindings, and verify retained original reads. Release Pages/Functions with the public-event bridge only. Confirm its build/source identity and exact served ZIP/sidecar. The checked-in Cron becomes active only on deployment; record that fact separately from source inspection. Do not activate the optional monitoring backend as part of Exposure acceptance.
6. **Run hosted HTTP/browser evidence.** Retain dated captures/cache hits, hashes/lengths, large-payload results, visible discovery and failures, concurrency/interruption/cap refusal and recovery behaviors. Exercise dangerous faults, cleanup and restoration only within the explicitly approved disposable targets. Use normal API/browser retrieval to reproduce a saved local case after restoration. Capture actual CPU/wall/resource observations without treating sampled memory as peak memory or HTTP elapsed as CPU.
7. **Prove the operational boundaries.** Record an idle observation interval and correlated request/provider traces; do not poll Neon to observe its own idleness. A scheduled backup may query metadata at its configured time; it may not perform source discovery/capture. Inspect browser network/storage, server configuration and packaged artifacts for credential/insured-data leakage. Save a complete recovery inventory outside Neon, measure snapshot freshness and total restore time including provisioning and transfer, and verify failure/old-point alerting.
8. **Return the evidence for Vineet's decision.** Explain every failed or unproven fit. A local 0.45-second restore is not a hosted working-day recovery proof. If accepted free-plan constraints cannot support the agreed journey or recovery objectives, reopen CAT-44 rather than add paid compute, alter providers, discard originals or weaken reproducibility. Keep activation pending until Vineet reviews and explicitly decides.
