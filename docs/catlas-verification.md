# Demonstration release verification

Internal verification performed 16 October 2026 on macOS arm64. CAT-13 through CAT-21 application behavior is implemented. CAT-22 artifact preparation is complete; Cloudflare authentication/account selection/publication remains the separate operator step. No hosted URL is claimed by this report.

## Results and tested environments

- TypeScript/Vite static production build passes. Vite reports the expected large MapLibre/application chunks; this is a size warning, not a build failure.
- All 97 Vitest checks pass. The integrated baseline's 50 development browser checks previously passed and cover additional validation, storage compatibility/failure, concurrent sends and stale replacements; release packaging does not alter application code.
- Six production acceptance checks pass using pinned Playwright Chromium (installed chromium-1228), across 1440×1000 desktop and 375×812 mobile viewport projects.
- The same six checks pass in installed Google Chrome 155.0.8059.80 on both viewports. Microsoft Edge is not installed here and was not executed. Mobile viewport emulation is usability coverage, not certification of a physical mobile browser.
- Both browser runs serve the **extracted zip** using its bundled Python standard-library launcher on http://127.0.0.1:4178. They block external browser networking and source-module paths. They use real downloads, IndexedDB and public UI/export boundaries, without Vite/dev source imports.

## Artifact and distribution

`npm run package:offline` supplies actual installed runtime dependency license/notice texts, source credits, a copy of genuine capture metadata, presenter instructions, static assets and the loopback Python launcher. Every bundle file is hashed in `release-manifest.json`; `npm run test:offline` extracts the zip and validates these digests before browser execution. `release/catlas-offline.zip.sha256` is the measured archive digest. Packaging time/commit/dirty state are recorded separately from historical evidence provenance; ZIP entry timestamps are explicitly normalized container metadata.

`release/pages/` contains the same application assets, licenses, evidence and presenter documentation plus the downloadable offline zip/sidecar. It is the concrete Cloudflare Pages deployment directory. Repackaging never copies a prior zip into the new offline zip. All generated output is ignored by Git.

The verified release can be copied intact into the main workspace. After publication, verify the actual HTTPS URL and downloadable zip against its SHA-256 sidecar. Local and hosted browser histories are separate origins. No authentication, account provisioning, Cloudflare publication, real RAS integration, financial approval or customer validation was performed by artifact preparation.
