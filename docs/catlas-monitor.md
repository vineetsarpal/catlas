# Monitor

Open `/?mode=monitor` or `exposure.html?mode=monitor`, or choose **Monitor** in the top navigation. Monitor, Exposure and Recovery share the header, with Portfolio available on the right. Catlas keeps its MapLibre map, appearance controls, geography and existing Exposure/Recovery workspaces. No backend or provider key is required.

Monitor discovers the past 24 hours of USGS earthquakes and NOAA NHC/CPHC cyclone advisories. The map has separate **Layers** and **Appearance** menus. Layers contains switches for earthquakes, tropical cyclones, insured locations and wind. **Fit portfolio** appears under Insured locations only while that layer is enabled. Appearance contains Light/Dark map, Globe view (on by default; off returns to a flat map with horizontal panning and a zoom-out limit that avoids repeated regions), borders and place labels. Each switch reveals its related details only while enabled; wind includes pause, shading and forecast-time controls. **Feeds** in Monitor details exposes per-feed check times/errors. Run time, valid time, advisory text and source-file timestamps are distinct. Only the surface U/V components are downloaded with bounded HTTP ranges from a single GFS 1° forecast object. A background worker decodes them into a numeric vector grid. The first use loads a lazy ecCodes WASM asset (~38 MB uncompressed, ~6.8 MB gzip); the UI stays interactive during decoding. A server could avoid this client download, but no backend is used. It is forecast context, not a location-level hazard assessment.

The attention list prioritizes event positions with more portfolio locations within 250 km. **Events within 250 km** is a geographic proximity filter, not an affected-exposure calculation. A cyclone center or uncertainty cone does not describe its full hazard footprint. Coverage is Atlantic and eastern/central North Pacific, not worldwide cyclones. Location points remain unassessed in Monitor and use a neutral portfolio color rather than exposure intensity colors.

Watch events or location points, switch to **Watchlist**, and optionally show watched items only on the map. Watchlist references and monitoring layer/filter preferences persist in localStorage on this browser and origin, with a 100-item watchlist limit. Events outside the rolling feed or disabled layers remain listed as unavailable watch references; they are not silently promoted to current observations. A local storage failure is reported and leaves session operation usable. The selected forecast time is session state and defaults to the provider's advertised current time after reload.

Selecting an earthquake offers **Capture evidence & investigate exposure**. Successful capture explicitly opens an exposure investigation using the loaded portfolio; missing ShakeMap produces unknown intensity with the existing explanation. Failed capture preserves the prior view and investigation. Source polling, forecast selection, watching and map filtering never rewrite an existing investigation or recovery evaluation. Frozen cases and reviewed packets remain in their existing storage and version lifecycle.

Monitor polls only while active, visible and online. Failed refreshes retain prior observations with unavailable/stale messaging; offline mode pauses acquisition. Wind display is hidden when offline or when a new vector field is pending/unavailable, preventing a previous field from being labelled with a newly selected time. Static geography and existing offline investigation workflows remain usable; no live-feed availability is promised offline. Feed state is retained during mode switches in the session, not persisted as evidence after reload.

Manage the existing location portfolio through **Portfolio**. Vessels, vessel imports, cargo relationships, marine exposure assessments, shared accounts/storage and the backend relay are deferred to CAT-35. The implementation is tracked in CAT-36.

Public source links, provider terms and the pinned God's Eye View reference/notice are in [monitor sources](../public/monitor-sources.md).

## Wind flow trial

Wind is now drawn as geographic streamlines on Catlas’s existing MapLibre map. Presentation includes **Pause wind** on the map toolbar, a **Pause wind motion** preference, optional **Show wind speed shading**, a knots legend and the model run/forecast valid time. Trail motion is accelerated for readability and never advances the forecast time. Reduced-motion preferences show static streamlines. The draw loop stops while the page is hidden, the map is moving, the layer is off, offline, or another mode is selected; paths are recalculated after the camera settles. Both regional Mercator and globe views use the same numerical field.

Catalog checks use a five-hour publication lag and can fall back one six-hour cycle if an inventory is missing. The time selector offers GFS three-hour steps through 48 hours; a missing forecast is reported as unavailable. The decoder verifies the selected run, valid time, component names, 10 m level, units, matching grids and scan direction. Full-file responses and oversized/short range bodies are rejected. Only the most recently decoded field is cached in session memory, for up to five minutes; decoded wind is not saved as investigation evidence. Switching the forecast cancels pending work.

The Vite asset plugin emits the pinned decoder’s WASM, runtime, adapted ESM wrapper and license into `wind-decoder/` in production. The WASM bytes are gzip packaged below Cloudflare Pages’ 25 MiB asset limit and verified against a generated SHA-256 manifest before compilation. The same files are served locally in development; no decoder asset is requested until wind is enabled. Source changes only convert exports to ESM and guard a Node-only Buffer check; no Node polyfills or runtime eval are added. The packaged offline download includes the decoder, but acquiring a current wind forecast still needs the network.
