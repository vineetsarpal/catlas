# Monitor

Open `/?mode=monitor` or `exposure.html?mode=monitor`, or choose **Monitor** in the top navigation. Monitor, Exposure and Recovery share the header, with a dedicated Portfolios destination and an active portfolio selector. Catlas keeps its MapLibre map, appearance controls, geography and existing Exposure/Recovery workspaces. Earthquake and cyclone discovery need no backend or provider key. Wind requires the Catlas backend; vessel monitoring also uses it.

Monitor discovers the past 24 hours of USGS earthquakes and NOAA NHC/CPHC cyclone advisories. The left tool rail opens **Attention**, **Locations**, **Watchlist**, **Feeds**, and **Layers** options. Selected items open in the right details panel; the map stays in the center. On mobile, opening options closes details and selecting an item closes options. The map has **Filters** immediately before **Appearance**, with north and zoom controls at the shared top-right position. Layers groups controls in **Portfolio → Hazards → Weather** order. Portfolio contains insured locations and vessels; Hazards contains earthquakes, tropical cyclones and Fires (perimeters, detections and the shared distance setting); Weather contains wind and weather warnings. Fire detections, Fire perimeters and Weather warnings each use one switch for monitoring and map display. **Fit portfolio** appears under Insured locations only while that layer is enabled. Appearance contains Light/Dark map, Globe view (on by default; off returns to a flat map with horizontal panning and a zoom-out limit that avoids repeated regions), borders and place labels. Each switch reveals its related details only while enabled; wind includes pause, shading and forecast-time controls. **Feeds** in Monitor details exposes per-feed check times/errors. Run time, valid time, advisory text and source-file timestamps are distinct. The backend downloads only the surface U/V components with bounded HTTP ranges from a single GFS 1° forecast object and decodes them in a Node worker. The browser receives validated numeric vectors and renders them; it downloads no decoder or WASM assets. It is forecast context, not a location-level hazard assessment.

The attention list ranks published warning/perimeter intersections before proximity matches and then by flagged location count. **Filters → Relevant to portfolio** retains known matches and items whose missing boundary prevents screening. Earthquakes and cyclones retain 250 km point proximity; fires use the adjustable fire distance. These are investigation attention flags, not damage assessments. A cyclone center or uncertainty cone does not describe its full hazard footprint. Coverage is Atlantic and eastern/central North Pacific, not worldwide cyclones. Location points remain unassessed in Monitor and use a neutral portfolio color rather than exposure intensity colors.

The shared **Filters** popover has two switches without descriptions underneath: **Relevant to portfolio** and **Watchlist items**. Portfolio relevance narrows Attention and the map; Watchlist items narrows only the map, leaving Attention, Locations and the saved Watchlist accessible. The button shows the count of enabled filters. Attention has a compact filter summary and **Map filters** link; the hazard dropdown and search remain local to its list. Locations and Watchlist do not repeat these switches or the matching explanation. **How matching works** is collapsed inside Filters and shows the current fire distance, with editing still under Layers → Fires. Escape, another map menu or a click outside dismisses Filters. On mobile, opening it from Attention closes the sidebar so the map controls remain usable.

Watch events or location points, switch to **Watchlist**, and optionally show watched items only on the map. Watchlist references and monitoring layer/filter preferences persist in localStorage on this browser and origin, with a 100-item watchlist limit. Events outside the rolling feed or disabled layers remain listed as unavailable watch references; they are not silently promoted to current observations. A local storage failure is reported and leaves session operation usable. The selected forecast time is session state and defaults to the provider's advertised current time after reload.

Selecting an earthquake offers **Capture evidence & investigate exposure**. Successful capture explicitly opens an exposure investigation using the loaded portfolio; missing ShakeMap produces unknown intensity with the existing explanation. Failed capture preserves the prior view and investigation. Source polling, forecast selection, watching and map filtering never rewrite an existing investigation or recovery evaluation. Frozen cases and reviewed packets remain in their existing storage and version lifecycle.

Monitor polls only while active, visible and online. Failed refreshes retain prior observations with unavailable/stale messaging; offline mode pauses acquisition. Wind display is hidden when offline or when a new vector field is pending/unavailable, preventing a previous field from being labelled with a newly selected time. Static geography and existing offline investigation workflows remain usable; no live-feed availability is promised offline. Feed state is retained during mode switches in the session, not persisted as evidence after reload.

Manage named insured-location inventories through **Portfolios**. Monitor uses the active selection, which persists in this browser; historical exposure snapshots remain separate. The vessel watch portfolio is a separate monitoring inventory. The local backend supports viewport vessel monitoring and vessel-list import (CAT-35). Cargo relationships, marine exposure assessments and shared accounts/storage remain deferred. The implementation is tracked in CAT-36.

Public source links, provider terms and the pinned God's Eye View reference/notice are in [monitor sources](../frontend/public/monitor-sources.md).

## Wind flow trial

Wind is now drawn as geographic streamlines on Catlas’s existing MapLibre map. Presentation in the left Layers panel includes a **Pause wind motion** preference, optional **Show wind speed shading**, a knots legend and the model run/forecast valid time. Trail motion is accelerated for readability and never advances the forecast time. Reduced-motion preferences show static streamlines. The draw loop stops while the page is hidden, the map is moving, the layer is off, offline, or another mode is selected; paths are recalculated in short, cancellable batches as soon as the camera settles, with motion resuming before the full viewport is rebuilt. Trail segments share batched canvas strokes to limit per-frame drawing overhead. Both regional Mercator and globe views use the same numerical field.

Catalog checks use a five-hour publication lag and can fall back one six-hour cycle if an inventory is missing. The time selector offers GFS three-hour steps through 48 hours; a missing forecast is reported as unavailable. The decoder verifies the selected run, valid time, component names, 10 m level, units, matching grids and scan direction. Full-file responses and oversized/short range bodies are rejected. The backend caches four decoded fields; the browser retains the most recently received field for up to five minutes; decoded wind is not saved as investigation evidence. Switching the forecast cancels the browser request; backend work can still finish and populate its bounded cache.

Wind acquisition, GRIB decoding and validation run only on the backend. Standalone and packaged offline builds show a disabled Wind switch with **Wind requires the Catlas backend.** Existing saved wind preferences cannot trigger browser decoding or direct NOAA wind requests. A configured backend failure is reported as unavailable; **Retry wind forecasts** retries discovery and vector loading without a browser fallback.

## Optional local backend

CAT-35 provides backend wind decoding and viewport vessel monitoring. See [backend setup](catlas-backend.md). With `VITE_CATLAS_BACKEND=true`, wind grids are fetched from the local backend. No browser decoder is shipped. The vessel layer offers Portfolio / All vessels, CSV import, recent trails and per-position report times. Browser-only and offline builds remain the default. Public deployment is deferred.

## US/Canadian fire and weather attention

The optional local backend now supplies three monitoring endpoints with independent provider caches: NASA FIRMS VIIRS NOAA-20/NOAA-21 and NRCan CWFIS satellite detections; NIFC WFIGS perimeters plus CWFIS reported incident points and estimated burned areas; and weather alerts combining a property-focused selection of US NWS watches, warnings and advisories with Canadian ECCC warnings, watches, advisories and statements. FIRMS uses a broad US regional envelope including Alaska and Hawaii; neighboring countries can appear in that envelope. These feeds are regional, incomplete and distinct from global hazard coverage. FIRMS requires `FIRMS_MAP_KEY` in `backend/.env`; CWFIS, NIFC and weather alerts need no provider key. Canadian hotspots remain usable without FIRMS credentials. All three require `VITE_CATLAS_BACKEND=true` and the running backend. Standalone/offline builds explain their unavailability.

The left Layers panel uses a single switch per feed (**Fire detections**, **Fire perimeters** and **Weather warnings**) for both monitoring and map display. All configured feeds monitor and display by default. Disabling a monitoring switch stops client acquisition and removes that feed from attention. Previous fire-detection, fire-perimeter and weather-warning visibility preferences are ignored; the saved monitoring switch determines both behaviors. Requests run only while Monitor is active, visible and online. FIRMS clients check every ten minutes against a thirty-minute backend cache; perimeters every five minutes; weather alerts every minute with independent one-minute NWS and ECCC backend caches. Backend cache acquisition occurs on demand, not through a background monitor or notification service.

Portfolio attention combines existing events with named fire incidents, per-location groups of nearby satellite detections and weather alerts. A hazard selector filters the list. Published-area intersections rank ahead of proximity matches; the list does not create a severity score across hazards. Under **Fires**, the shared **Flag locations within … km of fire activity** setting appears only while Fire detections or Fire perimeters monitoring is on. It defaults to 10 km and can be changed from 0 to 100 km; switching both feeds off hides the control and retains its value. Earthquake/cyclone point proximity remains 250 km. Perimeter distance is measured to the published boundary; warning screening uses the supplied polygon or complete official NWS zone boundaries. Polygon holes, multipolygons and dateline crossings are handled. Fuller, unsimplified WFIGS geometry is used for screening rather than God's Eye View's display-generalized boundaries.

Each fire/warning item explains its screening reason and reports distinct flagged location counts, TIV separately by currency, and unknown-value counts. These are attention flags, not physical damage, insured loss or a contractual recovery. A location can appear under multiple events; per-event values must not be summed as a portfolio loss. Multiple satellite observations can describe one fire. No named incident is inferred from a group of nearby detections, and satellite points are not burned-area polygons. Raw hotspot dots retain satellite detection coordinates; the attention groups refer to portfolio locations.

FIRMS and CWFIS observations expire after a rolling 24 hours, including when cached data is served during an outage. Perimeters display source-update time and age independently of feed acquisition time; no arbitrary age cutoff establishes whether a fire remains active. Current WFIGS publication is not a verified complete active-incident census. Invalid or missing boundaries remain visibly unscreened. Expired/cancelled warnings leave active attention. Watches follow incident identifiers and NWS update/reference chains, remain browser-local, and retain ended/unavailable references. This release stores no hazard evidence history or new Exposure investigation type.

Partial-source warnings, rejected records and stale retained evidence appear in Feeds. The attention panel signals degraded coverage. Missing boundary geometry means area screening is unavailable rather than zero matching locations; reported CWFIS incident points explicitly support proximity screening only. Feed refreshes and current attention never change existing Exposure or Recovery evidence versions.

### Fire map presentation

When fire detections are shown, nearby satellite observations form labeled detection groups at broad map scales. Click a group to zoom to its observations. Closer views show a small hotspot core with a static glow; marker size does not encode thermal power or damage. A selected detection stays highlighted even when surrounding observations regroup. Group counts describe satellite observations, not distinct incidents or burned area. Grouping changes only the display and never changes portfolio screening or flagged TIV.

Published fire perimeters use reported containment colors: unknown (gray), 0% (red), above 0% but below 50% (orange), 50% to below 100% (ochre), and 100% (green). Expand **Fire perimeters · containment** in the map legend for the key. Containment does not establish location safety. Incident labels show boundary age and avoid overlaps; selecting an incident fits all published polygon parts, including boundaries crossing the dateline, within the available map viewport.

Selecting visible fire activity opens a compact map card with source age, available portfolio attention and a browser-local watch action. The right inspector retains the fuller evidence and location list. Incident cards show flagged TIV separately by currency and unknown-value counts; individual detection cards show nearby location counts. Degraded source coverage is identified on the card. On mobile, use **Details** to close the inspector and return to the map card. Switching off either fire feed removes its map display and current attention results while preserving saved watches.

### Canadian fires (CWFIS)

The existing **Fire detections** switch includes CWFIS last-24-hour satellite hotspots. **Fire perimeters** also includes national agency-reported active incident points and rough satellite-derived burned-area polygons with detections in the past seven days. Canadian incident points are shown as markers; portfolio attention measures distance to the reported point and states that a boundary was not supplied. Estimated polygons use full published geometry for screening, with **Inside estimated fire area** / **Near estimated fire area** reasons. They are labelled **Estimated fire area**, not agency-mapped boundaries or observed current burning throughout the area. Reported locations and estimated areas are separate evidence; Catlas does not infer a link or sum them as distinct fire incidents.

CWFIS uses the documented CWFIF `public:cwfif_national_activefires` service and legacy `public:hotspots_24h` / `public:m3polygons` WFS layers. Explicit record-validity and observation-time filters prevent historical layers from appearing as current evidence. Stable national incident IDs and hotspot/polygon UIDs are used rather than GeoServer's generated feature IDs. Current incident validity is authoritative even when the underlying agency status report is old: **Status reported** remains visible separately from acquisition time. Native control-status codes remain provider fields; only an actual reported containment percentage is used as containment. Negative provider sentinels remain unknown. Estimated polygons show **Last hotspot** time; their publication time and containment remain unknown.

The backend caches CWFIS incidents for ten minutes and hotspots/estimates for thirty minutes. The browser continues checking detections every ten minutes and the incident/perimeter endpoint every five minutes. All three CWFIS acquisitions have independent failure retention and source status in **Feeds**, alongside FIRMS and NIFC. Failed/truncated acquisition retains that dataset's prior complete evidence. Complete successful refreshes remove withdrawn records. Hotspots, incident record validity and the seven-day estimate activity window expire in backend and browser retained evidence even during outages. CWFIS satellite coverage can include neighboring areas and overlap FIRMS; detection counts remain observations. No portfolio coordinates or values are sent to CWFIS.

### Canadian weather alerts

The existing **Weather warnings** switch includes ECCC's national GeoMet weather-alert collection alongside US NWS alerts. Canadian polygons are used directly for portfolio attention; missing or invalid boundaries remain unscreened. Each ECCC item represents a provider alert area, so multiple areas can describe the same weather event. Flagged TIV remains separate by currency and is not summed across overlapping alerts as loss.

Details identify **ECCC · Canada**, the named area/province, alert type, provider status, publication time, forecast valid time, event end and effective expiry. Native risk colour, impact and confidence remain ECCC fields; they are not converted into NWS severity/certainty/urgency or a shared hazard score. English text is shown initially, with French text under **Français**. Source links lead to the official feature record. Expiry is the earlier of message expiration and a supplied event end; future forecast validity does not suppress an already published advance alert.

NWS and ECCC acquisition/staleness are reported separately in Feeds. A failed or incomplete provider refresh retains that provider's earlier evidence with stale messaging; another provider's valid alerts remain available. Successful complete acquisition can remove ended or withdrawn items. Expired/ended/cancelled ECCC alerts leave active attention even during outages. Unknown statuses and invalid required timestamps are rejected with partial-coverage messaging.

Watches retain the namespaced ECCC provider feature identifier. Updates with the same identifier refresh the watch. The GeoMet collection does not supply CAP reference chains: a changed identifier remains a separate item, and an unavailable watch is not silently reassigned by matching its place or hazard name. Existing NWS CAP-reference watches remain supported. Source polling does not create an Exposure investigation or rewrite existing evidence versions.
